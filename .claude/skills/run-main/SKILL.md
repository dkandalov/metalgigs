---
name: run-main
description: Run the app's main entry point to scrape gigs, classify their genre, list unclassified gigs, manually override a gig's genre, render the HTML page, prune orphaned cached images, or all of scrape+classify+render. Use when asked to run the app, scrape gigs, classify gigs, list unclassified gigs, override/correct a gig's genre, clean up stale cached images, or render the gigs page.
---

Run `.claude/scripts/run-main.sh [scrape [venue-key...]|classify [limit]|unclassified [limit]|override <url> <metal|other>|render [yyyy-mm-dd]|prune-images|all]` from the project root using the Bash tool, e.g. `.claude/scripts/run-main.sh override https://example.com/event metal` (the script joins all its args into one `--args=...` string for `gradlew run`, so passing them as separate words or one quoted string both work — this also means venue keys and other args must not contain spaces, since gradlew resplits on whitespace).

A gig only counts as classified once its Keywords and LLM classifications agree (a `ClassificationStatus.Classified(genre)`); if they disagree it's `Disputed`, and if only one of them has run yet it's `Pending` — both stay out of the rendered Metal page until resolved. A `source = User` override (via `override`) is always final regardless of what Keywords/LLM said or whether both have even run.

- `scrape [venue-key...]` fetches gigs and appends a `GigObserved` entry per gig to `events.ndjson` (the append-only event log; never overwritten). With no venue keys, scrapes all eleven venues; with one or more keys (e.g. `scrape dome underworld`), scrapes only those. Known keys: `cart-and-horses`, `new-cross-inn`, `our-black-heart`, `underworld`, `dome`, `blondies-taproom`, `blondies-bar`, `helgis`, `electric-ballroom`, `dingwalls`, `the-garage`. An unknown key fails fast with the list of valid keys.
- `classify [limit]` projects the current gigs from `events.ndjson` and always runs both classifiers: for any gig its Keywords classifier hasn't classified yet, fetches the event page and matches keywords against the page text (`source = Keywords`, `matchedKeywords` populated); independently, for any gig its LLM classifier hasn't classified yet, sends the title and page text to Claude Haiku via `http4k-ai-llm-anthropic` for a Metal/Other judgement (`source = LLM`, no `matchedKeywords`, non-deterministic). Each gig's two passes are tracked independently — a gig already classified by Keywords but not LLM only gets the LLM pass this run, and vice versa; a `source = User` override on a gig counts as settled for both passes and is skipped by both. Requires an `ANTHROPIC_API_KEY` environment variable (fails fast with a clear message if missing) and makes a real paid API call per not-yet-LLM-classified gig. With a numeric `limit` (e.g. `classify 5`), each pass independently classifies at most the next N soonest-upcoming gigs it hasn't touched yet — useful for bounding cost/time. Poster images are cached only for gigs that reach Metal consensus as a result of the current run.
- `unclassified [limit]` projects the current gigs from `events.ndjson` and prints the ones not confirmed Metal by consensus — never classified at all, `Pending` (awaiting Keywords or LLM), `Disputed` (Keywords and LLM disagree), or agreed `Other` — sorted soonest-first, grouped by venue with a per-venue count, date/title/url per gig, with a trailing total count. With a `limit` (e.g. `unclassified 5`), only the next N soonest-upcoming ones are shown, and the trailing count reads "N (of M total)". No network calls.
- `override <url> <metal|other>` appends a `GigClassified` entry with `source = User` for the gig with that url, asserting its genre directly and finally — it always wins regardless of what Keywords/LLM said or will say, and a later `classify` run skips it entirely (both passes). No network calls.
- `render [yyyy-mm-dd]` projects the current gigs from `events.ndjson`, keeps only the ones confirmed Metal by consensus (never-classified, `Pending`, `Disputed`, and agreed-`Other` gigs are always excluded — there's no way to render them), excludes gigs before the reference date (today's date by default, or the given `yyyy-mm-dd` if passed — a gig happening today still shows), and writes `index.html` (no network calls). Only consensus-Metal gigs are guaranteed to have a cached poster image (see `classify`/`override`), so this filtering isn't optional — anything else would risk broken `<img>` tags.
- `prune-images` deletes any file under `images/` that doesn't match a currently consensus-Metal gig's expected filename (computed with the same `localImageFileName` hash used to write them) — e.g. leftovers from a gig that lost Metal consensus (reclassified, disputed), or from before caching became Metal-only. Prints each removed filename and a trailing count. No network calls; safe to re-run (reports 0 removed once caught up).
- `all` (also the default when no argument is given) runs `scrape`, then `classify`, then `render` — it does not include `unclassified`, `override`, or `prune-images`, which are standalone. Since `classify` now always needs `ANTHROPIC_API_KEY`, so does `all`.

Report what was produced and surface any errors from the Gradle output.
